# Tuya MCP — 2026-09-16

## Obiettivo
Integrare i dispositivi Tuya di Home Assistant in Bot-tazzi tramite un MCP dedicato, senza esporre direttamente credenziali o API Tuya al backend.

## Architettura
- Home Assistant resta il gateway Tuya autenticato e la fonte di verità dello stato.
- MCP dedicato: `/run/ralf-tuya-mcp/mcp.sock`.
- Il server verifica che ogni entità appartenga realmente a una config entry `tuya` di Home Assistant.
- Tool MCP: `tuya_health`, `tuya_list_devices`, `tuya_list_entities`, `tuya_get_state`, `tuya_call_service`.
- Il normale `HomeWorkflow` usa `TuyaMCPHomeBackend` quando `RALFLOOP_HOME_PROVIDER=tuya_mcp`.

## Sicurezza e policy
- Inventory e letture possono vedere le entità Tuya registrate in Home Assistant.
- Le scritture sono limitate a servizi reversibili allowlisted.
- Ogni scrittura fa read-before / call-service / read-after.
- Il `HomeWorkflow` conserva la propria policy sulle entità controllabili: il MCP non aggira la registry applicativa.
- Broker Unix autorizzato agli UID 1000 e 1001; nessuna shell generica esposta.

## Integrazione routing
- `tuya.home.mcp` è registrato come provider delle capability `home.state.read` e `home.service.call`.
- `config/mcp_catalog_v1.json` include il provider live `tuya`.
- `unified_route_probe` dichiara `tuya.home.mcp` quando il provider Home selezionato è `tuya_mcp`.
